---
title: Security (allowedTools)
description: The unified sandbox model — what a task may do, enforced before anything spawns
---

Every runner ships a **sandbox** on top of its transport: a deny-by-default-style
allowlist of *tools* a task may use, enforced **before anything spawns** — no
process, container, connection or tool call happens for a non-allowlisted tool.

The model is uniform across runners:

- **Per-task** — `config.allowedTools` declares what *this task* may do. Omitted
  → allow all (the runner ceiling still applies).
- **Runner ceiling** — `options.allowedTools` (daemon: the `runners` block in
  tasks.json) is the *maximum* the runner may ever run. A task whose
  `config.allowedTools` is not a subset of its runner's ceiling **fails at
  load**, before any run.
- **Validation order** — policy first, mechanics second: `allowedTools` shape →
  ceiling subset → runner-specific config (image/command presence, etc.).
  Enforced at load (fail-fast) **and** at every run (a task upserted after
  start is checked too).

## Tool spec format

Uniform pattern language: **exact match or trailing-`*` prefix** (`node`,
`python*`, `alpine:*`, `read_*`). Leading wildcards are not supported. What a
"tool" means is per runner:

| Runner | Tool identity | Example |
|---|---|---|
| [process](runners/process) | `argv[0]` (the executable) | `["node", "python*"]` |
| [ssh](runners/ssh) | first token of `config.command` | `["backup.sh", "systemctl*"]` |
| [docker](runners/docker) | `image@command` (both dimensions) | `["alpine@echo", "registry/*"]` |
| [mcp](runners/mcp) | `server:tool` | `["node:read_*", "https://mcp.example.com:*"]` |

### Docker: `image@command`

Docker restricts **two** dimensions — image and explicit entrypoint — in one
spec, separated by `@` (image tags use `:`, so `image:cmd` would be ambiguous):

```json
{ "allowedTools": ["alpine@echo", "alpine", "*@echo"] }
```

- `alpine@echo` — image `alpine`, only when the explicit command is `echo`
- `alpine` (no `@`) — image `alpine`, any command (including the image default)
- `*@echo` — any image, only command `echo`

### MCP: `server:tool`

`server` is the server identity (the URL for http, `command[0]` for stdio), split
on the **last** colon (http servers with ports work:
`https://mcp.example.com:8443:read_data`). A stdio spec without a colon
(`["node"]`) means any tool on that server. Because http URLs carry `:`, a
server-only http spec must be written explicitly as `url:*`. A bare http spec
(`"https://mcp.example.com"` with no `:*`) fails at load with a clear error — it
would otherwise parse as server `https` and silently match nothing.

## Tasks.json

The runner ceiling lives in the top-level `runners` block — policy next to the
desired state:

```json
{
  "runners": {
    "process": { "allowedTools": ["node"] },
    "docker": { "allowedTools": ["alpine@echo"] },
    "ssh": { "allowedTools": ["backup.sh"] },
    "mcp": { "allowedTools": ["node:read_*"] }
  },
  "tasks": [
    {
      "name": "export-captions",
      "runner": "process",
      "schedules": [{ "cron": "0 9 * * *" }],
      "config": {
        "command": ["node", "/opt/scripts/captions.mjs"],
        "allowedTools": ["node"]
      }
    }
  ]
}
```

Embedded hosts set ceilings directly:
`createDockerRunner({ allowedTools: ['alpine@echo'] })`.

## Security posture

- Omit = allow all (opt-in). A task that declares nothing keeps today's
  behaviour; the ceiling, when set, still applies at run time.
- A non-allowlisted tool never spawns — `failed` with a clear error, not a
  silent skip.
- The allowlist protects the daemon host / remote boxes / tool surface from a
  task whose config came from an untrusted source (agents authoring tasks).
